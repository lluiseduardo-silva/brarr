# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**brarr** is a Portuguese-language torrent search aggregator across UNIT3D-based trackers (locadora.cc, capybarabr.com, etc.). It scores releases by Portuguese audio/subtitle presence and quality, and will eventually expose a CLI, gRPC service, and Axum + Askama + HTMX admin web UI.

This is a personal Rust learning project. The author values quality, correctness, and architectural clarity over speed of delivery.

## Current State — Phases 1-6c complete

Implemented end-to-end pipeline plus rules engine, orchestrator service, and WASM plugin host:

- `brarr-mediainfo` (Phase 2): textual MediaInfo dump → `ParsedMediaInfo` + `ParseError`. Handles CRLF and LF, lenient to unknown fields.
- `brarr-core` (Phase 3): shared domain types — `Release`, `TrackerSource`, `Language`, `ReleaseEnrichment`, newtype IDs (`TmdbId`, `ImdbId`, `TvdbId`, `MalId`), `DecisionScore` (0..=1000), `ReleaseKind`, `Resolution`. Plus the `TrackerProvider` trait + `ProviderError` (Phase 6c).
- `brarr-tracker-unit3d` (Phase 4): async `reqwest`-based `Unit3dClient` with `search_by_tmdb` + `get_torrent`. Tolerant deserializers for the UNIT3D JSON variance between trackers. Implements `TrackerProvider`.
- `brarr-tracker-newznab` (Newznab/Torznab): async `reqwest` client for Newznab indexers (NZBGeek, DrunkenSlug, NZB.su, etc.) and Torznab Usenet-shape trackers. Hand-rolled `quick-xml` parser that collects `<newznab:attr>` entries (including repeated `audio`/`subs`) into a `HashMap` and maps `language`/`audio`/`subs` — plus the `language-audio`/`language-subs`/`lang` attrs that BR forks like Curupira emit — to `ReleaseEnrichment`. `Language::from_mediainfo` accepts English names, region names (`Portuguese (Brazil)`), and ISO codes (`pt-BR`, `pob`, `pt`, `eng`), so PT detection works across indexer dialects. Implements `TrackerProvider` via `search_by_imdb` (movie-search axis).
- `brarr-cli` (Phase 5 + remote subcommand): binary `brarr` with two subcommands. `brarr search` fans out locally from a TOML provider config. `brarr remote --addr host:port --token <t> {--tmdb <id> | --imdb <ttN>}` dispatches the search to a running `brarr-orchestrator` over gRPC (no local tracker config needed). Both render results through the same text/JSON formatter.
- `brarr-decision-service` (Phase 6a): declarative rules engine, TOML schema, `Engine::baseline()` reproduces the legacy Phase 5 scoring exactly. `Condition` is a **boolean tree** — beyond the flat AND of leaf fields it carries `all`/`any`/`not` combinators (recursive). Leaf predicates: `audio`/`subtitle`/`hdr`/`resolution`/`min_seeders`/`min_size_bytes`/`max_size_bytes`/`tracker`/`kind` (`web-dl`/`bluray`/`remux`/`encode`/`hdtv`/`dvd`)/`video_codec` (`x264`/`x265`/`av1`, accepts `h264`/`h265`/`avc`/`hevc` aliases)/`release_group`/`proper`/`repack`/`title_contains`/`title_matches` (regex). `kind`/`video_codec`/`release_group`/`proper`/`repack` read `Release.tags` (populated by `brarr_core::parse_release_tags` from the title; codec refined by MediaInfo in the UNIT3D converter). The `Engine` pre-compiles `title_matches` regexes; `RuleSet::validate()` reports invalid patterns to the profile editor. Adding new leaves was backward-compatible (all `Option`, no migration) — stored `rules_json` and the 5 presets are unchanged.
- `brarr-orchestrator` (Phase 6b + cross-crate integration): tonic gRPC server (`Brarr` service: `Search`, `ListProviders`, `RecentSearches`) + Axum admin web UI (dashboard, providers CRUD, releases history, search detail) backed by SQLite via `sqlx`. Server-side rendered with Askama templates + HTMX. **CSS is hand-authored and committed at `crates/brarr-orchestrator/static/app.css`** — there is no Tailwind and no frontend build step; the design tokens are CSS custom properties mirroring the Figma file, and dark mode swaps them via `:root[data-theme="dark"]`. Search fan-out goes through the `brarr_core::TrackerProvider` trait so UNIT3D direct clients, Newznab/Torznab indexers, and WASM plugins share one pipeline. The `providers` table has a `kind` column (`unit3d` / `newznab` / `torznab` / `plugin`) and a nullable `plugin_path`. Dispatch matrix: `plugin_path=Some` → `WasmTrackerProvider`; `kind=newznab|torznab` → `NewznabClient` (shared XML protocol); otherwise `Unit3dClient`. The gRPC `Search` RPC accepts `tmdb_id` and/or `imdb_id`; orchestrator dispatch prefers IMDb for Newznab/Torznab rows and TMDb everywhere else, falling back to the other axis when missing. A single `wasmtime::Engine` lives in `AppState`. Binary `brarr-orchestrator` launches both servers concurrently. **Terminology note**: pre-`a0b63a8` the configuration table was called `trackers`; migration `20260516120000_rename_to_providers.sql` renames it in-place along with FK + denorm columns in `decisions`.
- `brarr-plugin-host` (Phase 6c): wasmtime-backed sandbox that loads third-party tracker scrapers as core WASM modules. Runs in async mode (`Config::async_support`) with epoch interruption (`Config::epoch_interruption`) so host imports can `.await` and runaway plugins trap on a per-call deadline. Plugin ABI v1 documented in the crate-level rustdoc (exports: `plugin_alloc/free`, `plugin_abi_version`, `plugin_name`, `plugin_search_by_tmdb`; imports: `env.host_log` and `env.host_fetch`). `host_fetch` is async, capability-gated by `HostCapabilities::fetch` plus an `allowed_hosts` allowlist, with a per-request timeout. `HostCapabilities::call_deadline` (default 5s) caps wall-clock CPU per call via a background epoch ticker (`WasmEpochTicker`); `max_memory_pages` (default 1024 = 64 MiB) caps linear memory via a `ResourceLimiter`. `WasmTrackerProvider` implements `TrackerProvider`.
- `brarr-orchestrator` (inbound webhooks, `src/web/webhooks.rs`): receives Sonarr/Radarr Connect → Webhook events at `POST /webhooks/{radarr|sonarr}/{arr_instance_id}` (auth via `?apikey=` / bearer / trusted-peer bypass), persists an audit row in `webhook_events`, and runs the search + optional auto-push in a background `tokio::spawn`. **Discoverability UI**: `/arr-instances` shows the ready-to-paste webhook URL per instance (copy button via `static/copy.js`); a `/webhooks` nav page renders the `webhook_events` audit log (`webhook_events::recent`). **Poll reduction**: `arr_instances.webhook_driven` (migration `20260613120000`, toggled from `/arr-instances`) makes the scheduled poller skip that instance — the manual "rodar agora" button still works. (autobrr support is deferred.)
- `brarr-orchestrator` (Torznab indexer endpoint, `src/web/torznab.rs`): exposes `/torznab/api` so Sonarr/Radarr can use brarr as a single virtual Newznab/Torznab indexer that fans out across every configured provider. Dispatch on `?t=`: `caps` returns an XML capability advert (movie-search: yes; tv-search: yes); `movie&{tmdbid|imdbid}` and `tvsearch&tvdbid[&season&ep]` run the full search pipeline and render the kept decisions as an RSS feed with `torznab:attr` blocks (category, size, seeders, peers, leechers, grabs, tmdb, imdb); `search` (free-text) returns a valid empty feed (axis not built); a missing/blank `t=` defaults to `caps` (so the bare base URL is testable in a browser; *arr always sends an explicit `t=`); unknown `t=` values return `400` with a Newznab `<error code="202">` payload. **Profile pre-filter**: `movie`/`tvsearch` accept `?profile=<uuid|name>` — when set, brarr keeps only releases whose score under that quality profile clears its `push_threshold` (so brarr's add_score rules apply on the pull path, not just *arr's own quality profile); absent ⇒ every found release. Unknown profile ⇒ `400` Newznab error. The `/settings` page surfaces the indexer URL + a profile picker (`crate::web::torznab::resolve_profile_filter`/`score_passes`). Auth accepts either `?apikey=<BRARR_AUTH_TOKEN>` (the *arr-native way) or `Authorization: Bearer <token>`. Categories are inferred from `ReleaseKind` + `Resolution`: movies vs TV via `S##E##` regex heuristic on the title, then `2030/5030` SD, `2040/5040` HD, `2045/5045` UHD, plus `2050` BluRay as a secondary subcat for movie BluRay rips. Per-item download URL falls back to a synthetic `brarr:///download/<release_id>` placeholder when the persisted decision row doesn't carry an upstream URL; an explicit `/torznab/download/{tracker}/{release}` proxy route remains future work. Hand-rolled XML via `quick-xml`'s element builder — no Askama templates touch this surface.

- `brarr-orchestrator` (pull-path performance, `src/search.rs` + `src/ttl_cache.rs` + `src/provider_cache.rs`): the Torznab/Newznab feed handlers call `run_search_cached` instead of `run_search`. Sonarr/Radarr blow one Interactive Search up into many near-identical indexer requests (per season/episode, once per configured feed), so without dedup each one re-fans-out and re-persists a `searches`+`decisions` set, stalling the *arr UI for minutes. Four guards: (1) **protocol-scoped fan-out** — `run_search_scoped(state, keys, ProviderScope)` filters the enabled providers before dispatch: `/torznab/api` only hits torrent-side providers (`unit3d`/`torznab`/plugin), `/newznab/api` only `newznab` rows (`ProviderScope::{Torrent,Usenet}`; admin UI / poller / gRPC / webhooks use `All` via the `run_search` wrapper). The scope mirrors `Protocol::matches_kind` on the render side (a test asserts they agree), so a feed no longer waits on providers whose results it would drop; (2) a short-TTL `TtlCache<(SearchKeys, ProviderScope), SearchRunOutcome>` in `AppState` (`SEARCH_CACHE_TTL`, 60s; `ttl=0` disables) collapses the duplicate burst onto a single fan-out per scope — `run_search_cached` returns `(outcome, cache_hit)`; the admin UI and poller still call `run_search` directly for fresh data; (3) `fan_out` caps each provider's dispatch with `tokio::time::timeout` (`PER_PROVIDER_BUDGET`, 15s) so one slow/timing-out tracker can't hold the whole search for the underlying client's 30s×retry window — it's reported as a timeout failure and the rest proceed; (4) a `ProviderClientCache` keyed by provider id + a config fingerprint reuses the built UNIT3D/Newznab HTTP client (warm `reqwest` connection pool + TLS) across requests; plugins are still rebuilt per call.

- `brarr-orchestrator` (observability, `src/db/metrics.rs` + `/health` page): two STRICT tables (migration `20260721120000`) answer "is the slowness brarr, the cache, or an upstream tracker". `provider_metrics` gets one row per provider per fan-out — duration, `ok`/`error`/`timeout` outcome, release count — written best-effort by `run_search_scoped` (`record_provider_metric`; a metrics failure never fails the search). `endpoint_metrics` gets one row per `/torznab/*`/`/newznab/*` request — `t=` function, HTTP status, latency as the *arr client saw it, and cache `hit`/`miss` (the search handlers attach a `SearchCacheMarker` response extension; the outermost `metrics_middleware` in `web/torznab.rs` reads it, so 401s and 400s are measured too). The `/health` admin page ("Saúde" nav) aggregates both over 24h in Rust (`provider_stats`/`endpoint_stats`: count, ok/erro/timeout, avg/p50/p95/max — nearest-rank ceiling percentile so small-sample p95 exposes the worst case — cache hit rate, last error) plus a recent-requests table. Metric rows are pruned with the same retention window (`db::metrics::prune` inside `run_prune`; `MaintenanceOutcome.metrics_deleted`).

- `brarr-orchestrator` (own library, `src/db/library.rs` + `src/db/grabs.rs`, migration `20260804120000_library.sql`): brarr's own catalogue, replacing "whatever the \*arr answers on `/wanted/missing`" as the wanted-list. `library_items` (UNIQUE `media_type,tmdb_id`; `imdb_id` stored canonical **with** the `tt` prefix — note `searches.imdb_id` stores the bare number, the two conventions are reconciled in code) → `library_seasons` → `library_episodes`. **Metadata is a cache, monitoring is state**: `library::upsert` refreshes only TMDB-owned columns on conflict, never `monitored` / `profile_id` / `root_folder` / `added_at`; `sync_seasons` rebuilds the tree while preserving per-season and per-episode monitoring flags. `grabs` is the durable acquisition record (deliberately *not* hung off `decisions`, which the retention sweep prunes after 7 days). **`grabs::reserve` is the idempotency barrier**: it inserts a `reserved` row with `ON CONFLICT DO NOTHING` *before* any network call and returns `Ok(None)` to the losers, so concurrent tasks can't both grab a release. Two partial unique indexes rather than one composite, because SQLite treats NULL as distinct from NULL and `episode_id` is nullable (movies and season packs would otherwise be unconstrained). `release_id_remote` is TEXT — the old push path ran `parse::<u64>().unwrap_or(0)` over non-numeric Newznab guids, collapsing every such release onto key 0.

- `brarr-tmdb` (metadata source): async `reqwest` client for the TMDB v3 API, modelled on `brarr-tracker-unit3d` (thiserror, tolerant deserialisation, same retry shape). Auth is the **v4 read access token** as `Authorization: Bearer` — the v3 API key is a different string sent as a query param, and passing it as a bearer yields 401. Surface: `search_movies` / `search_tv` / `find_by_imdb` / `find_by_tvdb` / `movie` / `tv` / `season` / `verify_token`. Two upstream behaviours are handled in `model.rs` rather than leaked: (1) **TMDB has no automatic language fallback** — `language=pt-BR` returns an *empty* `overview` when no translation exists, so the client appends `translations` and walks pt-BR → pt-PT → en-US in code; (2) **release dates are per country and per type** — digital is `type == 4`, physical `5`, theatrical `3`, resolved for BR first then US then any. `tvdb_id` exists for series only. `ATTRIBUTION` holds the exact ToU phrase (the shorter FAQ wording is *not* the one the terms require) and `image_url()` builds CDN URLs — brarr stores only `poster_path`, never image bytes, because the ToU forbid using TMDB as an image host and forbid caching metadata beyond six months. **Fixtures in `tests/fixtures/` are derived from the documented schema, not captured live** (every endpoint needs a token); see the README there — re-capture them once a token exists.

- `brarr-orchestrator` (TMDB bridge, `src/tmdb_sync.rs`): wires `brarr-tmdb` into the library tables. Pure conversions (`movie_to_item` / `tv_to_item` / `season_to_new`) are separated from the fetch-and-persist side (`add_movie` / `add_series` / `refresh`) so the mapping is unit-testable without a pool or a network. Config comes from `settings` first and env second (`BRARR_TMDB_TOKEN`), with keys `tmdb_token` / `tmdb_language` / `tmdb_country` / `tmdb_ttl_days`; a blanked setting reads as "use the default" rather than as an empty value. `canonical_imdb` reconciles the two IMDb conventions in the codebase — `searches.imdb_id` holds the bare number, `library_items.imdb_id` the `ttNNNNNNN` form. `AppError::Tmdb` is deliberately not `#[from]`: the conversion peels off 401 into an `InvalidInput` that names the read-access-token mix-up, and 404 into `NotFound`.

- `brarr-orchestrator` (library UI, `templates/library*.html` + the `/library*` routes): `/library` renders the catalogue as a poster grid or a dense list — both server-rendered, switched by `?view=`, with `?filter=` chips for movie/tv/unmonitored. `/library/add` is the TMDB search; adding a series also walks every season so the episode tree lands with the item. Monitor toggle and delete answer with `HX-Refresh: true` instead of a row fragment, because the row markup differs between the two layouts and a partial would mean maintaining it twice. **Season 0 is TMDB's specials bucket and is excluded from both halves of the tree summary** — The Boys carries 76 specials against 40 real episodes, so counting them would render "5 temporadas · 116 episódios". `/settings` gained a TMDB section; the credential field is write-only (never echoed back, blank means "keep the current one").
- `brarr-orchestrator` (library detail, `templates/library_detail.html` + `partials/library_season.html`): `/library/{id}` renders the TMDB hero (poster w342, status/runtime/release-date pills, external-id chips, synopsis), the season accordion for series, and the grab history. **Seasons are collapsed and their episodes load on demand** (`hx-trigger="click once"` → `GET /library/{id}/season/{season_id}`) — a long-running series carries a hundred-plus episodes and rendering them all up front costs a query and a lot of DOM for rows nobody opened. Season toggle cascades to its episodes and answers `HX-Refresh` (the open accordion body is stale after the cascade); episode toggle swaps just its own row, reusing `LibrarySeasonPartial` with a one-element vec. The theatrical-window alert fires only while `digital_release_at` is still in the future — verified discriminating on live data: of six titles, it fired on exactly the one whose digital date had not passed.
- `brarr-download-client`: async clients for the programs that actually move the bytes — **qBittorrent** (WebUI API v2) and **SABnzbd** (`/api` query interface), one per protocol, covering the UNIT3D/Torznab and Newznab provider families. Two implementations is what justifies the `DownloadClient` trait; it uses the same boxed-future shape as `TrackerProvider` so the orchestrator can hold `Box<dyn DownloadClient>`. **Both refuse credentials inside a `200 OK`** — qBittorrent answers the login POST with the literal body `Fails.`, SABnzbd with `{"status": false, "error": "API Key Incorrect"}` — so status code alone would report a wrong password as a healthy connection; hence `DownloadClientError::Auth` as its own variant and a body check in both impls. qBittorrent is cookie-authenticated: the `SID` lives behind a `tokio::sync::Mutex` (held across the login so a burst performs one login, not one each), an empty username means "the WebUI bypasses auth" rather than an error, and a `403` triggers exactly one re-login + retry because a SID dies on restart and on idle timeout. SABnzbd reads its version out of the `mode=queue` payload — the call that also proves the apikey works — and falls back to `mode=version` on older builds that omit it. Only `test_connection` for now; handing a `.torrent`/`.nzb` over reuses all of it.
- `brarr-orchestrator` (download clients, migration `20260804130000` + `src/db/download_clients.rs` + `/download-clients`): the `download_clients` table plus the `grabs.client_id` FK that `20260804120000_library.sql` deliberately left out (a REFERENCES clause pointing at a table that does not exist is not a constraint). **Protocol is not a column** — it is a function of `kind`, and a stored copy is a second source of truth that can drift; `pick_for_protocol` filters in Rust for the same reason. `ON DELETE SET NULL`, so removing a client blanks `grabs.client_id` without erasing the acquisition history. Secrets are write-only in the edit path: `update` reads `None` for `password`/`api_key` as "keep what is stored" (the modal never echoes a credential, so blank cannot mean "erase"), mirroring how `/settings` treats the TMDB token. The admin screen mirrors Figma screen 18 minus the "Pastas raiz" half, which belongs to the phase-2 import block; the client count and the "sem torrent"/"sem usenet" coverage badges live *inside* the HTMX swap target, because a count rendered in the page header still reads zero after the first client is added.
- `brarr-orchestrator` (the scanner, `src/scan.rs` + `src/deliver.rs`, migration `20260804140000`): brarr's own answer to "what am I missing", replacing the \*arr's. `scan::spawn` sweeps every monitored item on the `poll_interval` cadence; per target it searches, scores under the item's quality profile, reserves through `grabs::reserve` **before any network work**, and hands the release to a download client. **"Do I already have it?" is inferred from `grabs`** (`GrabStatus::blocks_search` — everything except `failed`/`rejected`), the operator's decision over scanning the disk; the accepted lie is a file deleted outside brarr. **TV is per-episode and conservative**: one target per monitored *aired* episode (season 0 excluded), on the TVDB axis, and a candidate is only accepted when its title carries the matching `S01E02`/`1x02` marker — a season pack recorded against one episode would make the rest of the season look acquired. The candidate loop walks releases best-first until one *wins a reservation*, because the barrier legitimately refuses releases a previous sweep marked `failed`. **`decisions.release_guid`** exists because the barrier needs a release key that is stable across searches and `release_id_remote` is INTEGER filled by `parse::<u64>().unwrap_or(0)` — every Newznab guid collapsed onto `0`. Delivery splits failures in two (`deliver.rs`): **transient** (client down, credentials refused) releases the reservation so the same release can be retried; **permanent** (the client rejected the file, the URL 404s) marks the grab `failed`, which *keeps* the barrier key occupied so the scanner moves to the next release instead of retrying this one forever. brarr fetches the `.torrent`/`.nzb` itself and shape-checks it (bencode `d`, XML `<`) rather than passing the URL through — a tracker answering its HTML login page with a `200` would otherwise become a download that silently never starts. The sweep no-ops entirely while no download client is enabled. `/library/{id}/scan` is the "buscar agora" button: it spawns the sweep and waits 10s on the `JoinHandle`, so a 40-episode series reports "em andamento" instead of holding the request open.
- `brarr-orchestrator` (queue tracking, `src/queue.rs` + `/queue`): closes the loop `deliver.rs` left open at `sent`. A background sync (`SYNC_INTERVAL`, 60s) asks each client about every in-flight grab and walks it `sent → downloading → completed`/`failed`. **The identity is the infohash** (`brarr-download-client`'s `infohash` module): qBittorrent's `torrents/add` answers a bare `Ok.` and names nothing, so the torrent side computes SHA-1 over the **bencoded `info` dictionary verbatim** — a decode-and-re-encode round trip would reorder keys and produce a valid-looking wrong hash, so the scanner locates the value's *byte span* instead. This is what Radarr does (`_torrentFileInfoReader.GetHashFromTorrentFile`, then `DownloadId = torrent.Hash.ToUpper()`); the category is **not** an identifier — Radarr's `GetItems()` does not even filter by it. SABnzbd keeps naming its own (`nzo_id`), and a job moves from `mode=queue` to `mode=history` when it finishes, so `status` reads the queue then falls through to the history. **"The client doesn't have it" and "I couldn't ask" are separate** (`Probe::Unknown` vs `Probe::Unreachable`): the first fails the grab after `MISSING_GRACE` (10 min, because both clients take a moment to list something just accepted), the second never touches it — a restarting container must not abandon a healthy download. **Progress/speed/ETA are never stored**: three columns rewritten every minute for numbers that are stale on arrival, when the queue is a handful of rows the client can answer for on demand. The `/queue` page reads live; pause/remove need a client control surface that does not exist yet.
- `brarr-orchestrator` (root folders, migration `20260804150000` + `src/db/root_folders.rs`): first half of the import block, and the only half that touches no files — the destination the importer will link into, declared up front. **The path is validated at registration, not at use**: a typo found at import time is a download that already finished, occupying disk, with nowhere to go, and the operator learns about it from a failed grab hours later; three syscalls at insert (exists / is a directory / is writable) turn that into a form error. `media_type` is **nullable** because brarr owns both kinds in one catalogue — NULL serves either, and `pick` prefers an exact match over it. Free space comes from `fs4` and is read per render rather than cached (it changes with every download); an unreadable path renders muted with "caminho inacessível" instead of a zero that reads like a full disk. Deleting a root folder forgets a destination, it does not unmake a library.
- `brarr-orchestrator` (the import, `src/import.rs`, migration `20260804160000`): the only code in brarr that writes to the operator's files. A background task (`IMPORT_INTERVAL`, 60s, its own task so a cross-device copy never stalls queue tracking) walks `completed` grabs: ask the client where it saved the download, pick the video, build a Plex/Jellyfin path, place it, `mark_imported` with the destination recorded in `grabs.imported_path`. **brarr parses nothing** — the grab already carries `item_id`/`episode_id`, so title, year and episode come from the catalogue rather than a regex over the release name; this is the largest simplification the block offers over Radarr/Sonarr, which must guess because a file can arrive from anywhere. Four rules protect files: **never overwrite** (`create_new`, so check and write are one syscall and no race fits between them), **never leave a partial** (a failed copy deletes what it wrote — half a video is worse than none because nothing downstream can tell it apart), **never remove from the client** (private trackers need the seed; hence `ImportMode::Hardlink` as the default, configurable to `copy`/`move` at `/settings`, with an automatic copy fallback when the library is on another filesystem), and **never guess a destination** (no root folder ⇒ the grab *waits* as `completed` and the next pass retries, rather than failing). File selection is largest-video-that-is-not-a-sample, with `sample` matched as a **token below the download folder only** — matching the whole path meant an operator whose downloads land in `/mnt/sample-disk/` could never import anything (caught by a test whose own temp directory contained the word). For an episode, a file naming the matching `S04E07` beats the largest, and an ambiguous multi-video folder is refused rather than guessed. `sanitize` applies Windows' rules everywhere (illegal characters, trailing dots, reserved device names like `NUL`).
- `brarr-orchestrator` (file verification, `src/verify.rs`, migration `20260804170000`): closes the one lie the scanner's "infer from `grabs`" answer carried — a file deleted outside brarr used to leave its item covered forever. Every 6h (and on the `/library` button) it `stat`s each `imported` grab's `imported_path`; a file that is gone gets `file_missing_at`. **That is a column, not a status, and the reason is the barrier**: marking the grab `failed` would let the scanner search again but leave the unique key occupied, so the one release the operator actually had could never be re-acquired — usually the exact release they want back. Deleting the row would free the key and destroy the history. The two partial unique indexes were rebuilt with `AND file_missing_at IS NULL`, which frees the key *and* keeps the row; the status stays `imported`, because it was. `is_gone` counts **only** `ErrorKind::NotFound` — a permission error or an unreachable mount is not a deletion, and treating it as one would re-download a library because a disk was busy. It does not adopt files brarr never imported; that is a different feature.
- `brarr-orchestrator` (interactive search, `GET /library/{id}/interactive` + `POST /library/{id}/grab/{decision_id}`): the manual counterpart to the sweep. **It calls `search::run_search_unfiltered`, not `run_search`** — the automatic path drops releases that *every* quality profile rejects (junk to everyone, and persisting it grows `decisions` for nothing), and `decisions_out` never carried a rejected row even when one was persisted. Both filters are correct for the sweep and exactly wrong for a screen whose purpose is showing what the rules would not take. Found against the production database: a search returning 102 releases from four providers rendered an empty table because both of the operator's profiles rejected all of them. The scanner picks the best release above the item's threshold; this shows everything the fan-out found and lets the operator choose a provider, an encode, or a **season pack**. The threshold becomes information — the score badge says which side of the line a release fell on — not a veto. **The barrier still applies**: choosing a release by hand does not make grabbing the same one twice safe, so it still goes through `grabs::reserve`. Series get a season picker (season 0 excluded, matching the scanner) and an optional episode number; blank episode = pack, which records `grabs.season_number` and names no episode. That is the first thing to fill that column, and it is what forced `blocking_for` to become season-aware.
- `brarr-orchestrator` (remote path mapping, `src/remote_path.rs` + `src/db/path_mappings.rs`, migration `20260806120000`): the download client and brarr do not have to see the same filesystem in the same place, and there is no way to make them — brarr's clients mount the media share at `/data` while brarr mounts it at `/midias`, because `/data` inside its image is already the sqlite volume. Found in production: five finished downloads marked `failed` while their files sat intact on disk. `path_mappings` is keyed on **`download_clients.id`, not a host string** — Radarr/Sonarr key on the retyped Host, which makes `localhost`/`127.0.0.1`/the container name/the IP four keys for one machine and silently orphans a mapping when the client is edited; brarr already holds the client row at the one point it needs the rule (`import.rs`'s `locate_download`, the **only** site where a client-supplied path enters — `verify` stats brarr's own `imported_path`). `ON DELETE CASCADE`, unlike `grabs.client_id`'s SET NULL: a grab without a client is history worth keeping, a mapping without one is dead configuration. **The remote side is never validated against the disk** (it names a directory on another machine and *should* not exist here); only the local side is, at registration, like `root_folders`. Matching is on **strings, not `std::path::Path`** — a Linux brarr parsing `C:\Downloads` with `Path` sees one component, so `starts_with` passes every Linux test and breaks on the case the feature exists for. Rules: prefix must end on a **component boundary** (`/data/down` cannot cover `/data/downloads`), **longest wins** (Radarr returns the first row, so overlapping rules resolve by insertion order), separators are a function of the detected flavour (**POSIX splits only on `/`** — a backslash is a legal Linux filename character, and `AC\DC` is one directory), a UNC root is a root (`\\NAS\midia` never covers `/NAS/midia`), POSIX components are case-sensitive and Windows/SMB are not, and `.`/`..` are resolved lexically before anything reaches the join. Translation **fails open**: an uncovered path passes through (normalised), because the layout where both sides agree needs no mapping and must keep working, and a wrong rule has to heal the queue the moment it is corrected. No disk probe once a rule matches — this operator's container *has* a real `/data`, so a fallback would reopen the hole.
- `brarr-orchestrator` (waiting is not failing, `import.rs`): `pick_video` used to collapse "I cannot see this path" and "what is here cannot be imported" into one `Err`, which `place_download` turned into `Permanent` → `failed`. Because `failed` deliberately **keeps the barrier key occupied**, the next sweep grabbed a *different* release, re-downloaded it, and failed identically — burning through every release for the episode, one per sweep. `PickError::{NotVisible, BadContent}` splits them: not-visible waits (the file may be one mapping away), bad-content stays permanent. One `metadata` call at the top replaces the `is_file()`/`is_dir()` pair that discarded the error, and an unreadable **top-level** `read_dir` (client uid ≠ brarr uid — the other half of the same Docker problem) is now `NotVisible` too instead of reading as "no video here". Two columns support it: `grabs.import_wait_reason`, because waiting lived only in a `debug!` log (deliberately not `error`, which means "failed" everywhere else and renders red beside a green pill), and `grabs.import_attempted_at`, because `awaiting_import` ordered by `updated_at` and waiting does not move it — three stuck grabs would sit at the head of a `MAX_IMPORTS_PER_PASS`-sized window forever. `queue::next_status` no longer fails a `completed` grab on `Probe::Unknown`: clearing a finished torrent out of qBittorrent is housekeeping, and failing it would drop the item out of `blocks_search` and restart the churn. Recovery is `grabs::requeue_import` (a single `UPDATE ... WHERE status = 'failed'`, so the clause *is* the lock and a double click is a no-op) surfaced per row on `/download-clients` — **no filtering by message**, because a predicate that guesses which failures a mapping would fix requeues permanent ones forever.
- `brarr-orchestrator` (add with options, `templates/partials/library_add_options_modal.html`, migration `20260806130000`): `POST /library/add` used to carry only `tmdb_id` + `media_type`, so destination, profile and monitoring were all invisible defaults. `GET /library/add/options` returns a `<dialog>` into `#modal-target` (the house modal contract) offering root folder, quality profile — each labelled with its `push_threshold`, and "sem perfil" labelled with `scan::DEFAULT_PUSH_THRESHOLD`, so the fallback is not itself invisible — monitoring scope, and "buscar agora". **`library_items.monitor_scope` has to be a column**: `sync_seasons` marks every row it has never seen as monitored, so "only the first season" expressed purely as per-season flags becomes "all seasons" the day TMDB publishes season 2. Its job is narrow — it decides the default for *unseen* rows and never overwrites a flag the operator set. There is deliberately no "latest season" variant: it would need an unseen row monitored *and* the previous one unmonitored, which one stored value cannot express. `add_with_options` fixes the order (scope → tree → placement) because `sync_seasons` reads the scope, and only touches placement when something was actually chosen — `set_placement` writes both columns unconditionally, so a re-add would otherwise erase a hand-set profile.
- `brarr-orchestrator` (importing the \*arr catalogue, `src/arr_import.rs` + `src/db/arr_root_mappings.rs` + `/arr-instances/{id}/import`, migration `20260807130000`): what makes brarr a replacement rather than a second opinion — 360 titles on this operator's stack, and re-registering them by hand is not a migration path. It also settles the hardest problem the disk importer left open, for free: **Sonarr already decided which file is which episode**, including absolute-numbered anime no marker regex reads. Verified live on 2026-08-07 — Yu-Gi-Oh! Duel Monsters, 224 files, 224 paired, and not one `SxxEyy` among them; the pairing test uses that real name and asserts `adopt::parse_marker` refuses it, which is the half that says *why* the feature exists. **The module writes nothing to disk** — no link, no copy, no rename, and no destination value anywhere in it, the same guarantee `AdoptAction::InPlace` gets from carrying no path. Each file is reserved through `grabs::reserve_local` and marked imported at its own path, so `is_in_place` holds and undo is one row delete. Path translation reuses `remote_path` (`PrefixRule` was extracted so `path_mappings` and `arr_root_mappings` share one tested matcher instead of two copies of the same sharp edges); **the root is mapped, not the path**, because an \*arr has one root and thousands of files under it — verified live: every catalogue row carries `rootFolderPath`, one distinct value per instance. Fail-open is kept, but the two failure counters are split: `unmapped` is a rule the operator has not written, `missing` is a rule that is wrong or a file that moved. **Monitoring, profile and root folder are written only for titles a run creates**, extending `db::library`'s "metadata is a cache, monitoring is state" to placement — a sweep that rewrote them would walk back every hand-made choice, forever. `MonitorChoice::Paused` sets `monitor_scope = Nothing` *before* the tree is built (`sync_seasons` reads it); `Mirror` copies the \*arr's flags season-first, because the season cascade wipes per-episode flags and a test pins that order. `arr_instances.sync_source` is **a different axis from `enabled`** — the operator's three instances are disabled for the deprecated push path while being exactly the catalogues brarr reads — and `sync_one`, the passive sweep's entry point, **takes no monitoring parameter at all**: those \*arr still have indexers aimed at the same clients brarr uses, so a synced title arriving monitored is the double agency this whole direction exists to end. The preview writes nothing and needs no TMDB credential (one catalogue call plus one `stat` per title), so it is safe against a live instance; the number it exists for is "pastas encontradas", where a wrong mapping reads `0/137` before anything instead of failing thousands of times later. `arr_sync_interval_secs` in `/settings` drives the background sweep, read fresh each cycle (default 30 min, floor 60s).
- `brarr-orchestrator` (library status, `src/coverage.rs` + `/library` + `/library/{id}`): the screens counted seasons and episodes and never said whether the operator *had* them. Two rules govern every number: **the denominator is what is monitored, never what exists** (a series with three of ten seasons monitored is complete or not *over those three*; counting against the catalogue makes every deliberately partial title read as permanently behind, and season 0 is excluded because the scanner never chases it), and **"aired" splits missing from merely unreleased** (one colour for both makes every returning series red forever). Hence six states rather than two — `complete`/`current`/`missing`/`upcoming`/`paused`/`nothing` — sharing one vocabulary across the card spine, the chip, the bar and the season header. An episode with **no** air date counts as unaired (TMDB blanks it until scheduled); a movie with **no** digital date counts as released (TMDB has none for most older films, and the opposite default would paint half a film library purple). **`ItemStatus::callout` is a different question from `Progress`**: a paused title keeps its per-episode flags, so it rendered a grey "pausado" chip beside red "4 faltando" — both true, and together a call to action brarr was never going to take; `callout` is what the card *flags*, and it is empty when paused. Episode rows carry the monitoring bookmark and the state mark as **separate columns on purpose** (an episode can be chased and absent, or paused and on disk), and the mark's tooltip carries the mapped file path — the thing that used to require reading the grab table row by row. A season toggle answers with its own episode rows **plus two out-of-band fragments** (its bookmark and its status group): it was an `HX-Refresh`, which closed the accordion just opened, and sending only the bookmark left a chip reading "faltando" over rows no longer monitored. The grab history moved into a dialog (`/library/{id}/grabs`) because inline it pushed the season tree below hundreds of release names. `/library` also stopped being N+1 — it called `seasons` and `episodes` per row, 720 round trips at 360 titles; four bulk queries now. **`tests/css_coverage.rs` gained the two changes this needed**: a trailing `-` counts as a prefix requirement (the first markup to build a class name from Rust), and `every_status_tone_has_a_rule` walks the real enums so a new variant with no rule fails the suite instead of rendering colourless. `examples/library_preview.rs` seeds one title per status in memory and serves them together — it is what caught the paused card, and it reaches no network, TMDB or disk.
- **A nested `<form method="dialog">` inside a `<form hx-post>` is not a cancel button.** Both existing modals had one, with `type="submit"` on the button. HTML forbids nesting, so the parser drops the inner tag and the button becomes a submit of the form around it — "Cancelar" ran the search / created the profile. Replaced with `type="button"` + `close()`.

- **`static/app.css` has a real button system (`.btn` + variant + size).** Before it, every button was a bag of utilities and the reset *deliberately withholds* `cursor: pointer` — with almost nothing opting into `.cursor-pointer`, no button in the app reacted to the mouse at all: no cursor, no hover, no pressed state, no disabled state. `.btn` carries behaviour (cursor, focus, `:active` translate, `:disabled` opacity + `not-allowed`), a variant carries colour (`btn-primary` / `btn-brand` / `btn-secondary` / `btn-ghost` / `btn-danger` / `btn-toggle-on`), a size carries metrics (`btn-sm`/`btn-md`/`btn-lg`, plus `btn-icon`). **`.btn.htmx-request` is the in-flight state** — HTMX stamps that class on the element issuing the request, so every button in the app got "am I working?" feedback at once with no per-button spinner markup. All 70 buttons across 27 templates use it.
- **The nav is six items, not thirteen.** Dashboard / Biblioteca / Fila / **Buscas ▾** / **Configuração ▾** / Saúde, the two menus built on `<details>` so they work before `nav.js` loads; the script only adds close-on-outside-click, one-open-at-a-time and Escape. `nav.js` marks a dropdown's `<summary>` active when any child route is, so the bar still says where you are.
- **`/settings` is split behind a side menu** (`?s=acesso|automacao|metadados|dados|integracao|diagnostico`, unknown falls back to the first). **Hidden sections stay in the DOM** — that is the whole design: the general form POSTs Conectividade, Workers, TMDB, Retenção, Import and Diagnóstico in one request, so slicing the POST would mean making every field "absent = keep", and a mistake there erases real configuration. `display: none` keeps the inputs in the submission; a live test round-trips a save from the "dados" section and asserts `import_mode` (which lives in "automacao") survives.
- **`tests/css_coverage.rs` restores what Tailwind used to catch at build time.** With `--color-*: initial`, an unknown utility simply failed to generate and the gap was visible; hand-authored CSS makes it silently inert instead. The test parses `static/app.css` for class selectors, strips Askama tags from every template (before locating attributes — conditional classes carry their own quotes) and fails on any class with no rule. It has already caught a real regression: `border-danger-solid/30` and `border-success-solid/30`, opacity variants Tailwind generated on demand and the migration dropped. **It scans `src/**/*.rs` too**, since `web/routes.rs` builds HTMX fragments as strings — that gap hid a second regression for the whole life of the migration: every connectivity badge the handlers emitted carried `bg-emerald-100 text-emerald-800`, a Tailwind palette scale the stylesheet never defined, so the pills rendered with no colour at all.

942 tests pass (`cargo test --workspace --all-targets`). `INITIAL_PROMPT.md` remains the authoritative spec — consult before adding crates, dependencies, or making architectural decisions.

### Running the orchestrator

```powershell
$env:Path = "C:\Users\pc\.cargo\bin;$env:Path"
$env:BRARR_AUTH_TOKEN = "$(openssl rand -hex 32)"  # optional but recommended
cargo run -p brarr-orchestrator
# → http://127.0.0.1:3000 (admin UI), gRPC on 127.0.0.1:50051
```

Env vars: `BRARR_DB_PATH` (default `./brarr.db`), `BRARR_HTTP_ADDR`, `BRARR_GRPC_ADDR`, `BRARR_STATIC_DIR`, `BRARR_AUTH_TOKEN`, `BRARR_DECISIONS_RETENTION_DAYS` (default `7`, `0` = keep forever), `BRARR_TMDB_TOKEN`.

**Background tasks** (all fire-and-forget, spawned in `main.rs`, staggered so they don't pile onto startup): the poller (immediate), the scanner (90s), the importer (120s), the passive \*arr sweep (150s), the db janitor (60s), plus queue sync and the file check. Each no-ops while its prerequisite is unconfigured — no download client, no root folder, no sync source, no TMDB token — so a deployment that never opens the corresponding screen sees no change in behaviour.

**History retention / DB maintenance**: the poller persists a `decisions` row per evaluated release every cycle, so the table grows unbounded without a retention policy. A background task (`src/maintenance.rs`, mirrors `poll::spawn`) wakes every 6h and prunes `decisions`/`searches` older than `BRARR_DECISIONS_RETENTION_DAYS` (hot-reloadable via `/settings`), preserving any decision referenced by `push_history` (pushed releases) and any search that still has decisions. SQL lives in `db::maintenance` (`run_prune`/`prune_decisions`/`prune_searches`/`checkpoint_wal`/`incremental_vacuum`/`full_vacuum`); `db::open` sets `auto_vacuum=INCREMENTAL` — but **that PRAGMA is a no-op on a database that already has pages**, so every install created before it was added still reports `auto_vacuum = NONE` and `incremental_vacuum` does nothing there. Verified on the production database: 2.95 GB of file for 28 MB of data, 713 605 of 720 659 pages free. Only a full `VACUUM` reclaims it (and only a full `VACUUM` changes the mode). On-demand triggers: `/settings` "Manutenção do banco" buttons (prune / VACUUM), the gRPC `RunMaintenance` RPC, and `brarr maintenance --addr <a> [--token <t>] [--vacuum]`. The one-time offline reduction for a large pre-existing DB is `scripts/db-maintenance.sql` — see `docs/DB-MAINTENANCE.md`.

When `BRARR_AUTH_TOKEN` is set, the UI requires a login at `/login` (sets a `brarr_session` HttpOnly cookie) and gRPC calls must present `authorization: Bearer <token>` metadata. When unset, the orchestrator logs a `warn!` once at startup and lets every request through (dev mode).

## Toolchain notes

- **Deployment target**: Linux (Docker). Windows local dev is supported but not the primary path.
- **Active toolchain on this machine**: `stable-x86_64-pc-windows-msvc` (rustc 1.95.0). Visual Studio 2022 Build Tools with the "Desktop development with C++" workload provides `link.exe` + `cl.exe`; crates with C build scripts (`aws-lc-sys`, `openssl-sys`, etc.) compile cleanly through MSVC.

- **MSRV** pinned to **1.85** (`edition = "2024"` requires it).
- **Dev container alternative** for Linux-native builds: `Dockerfile.dev` + `.devcontainer/devcontainer.json` + `docker-compose.dev.yml`. Run `docker compose -f docker-compose.dev.yml run --rm dev cargo test --workspace` for a one-shot Linux build, or open the repo in a Dev Container-aware IDE (VS Code, JetBrains Gateway → RustRover).

## Architecture (Planned crate layout)

Strict boundaries between concerns. Each crate has a single responsibility:

| Crate | Phase | Responsibility |
|-------|-------|---------------|
| `brarr-mediainfo` | 2 | Parse MediaInfo text dumps into structured types |
| `brarr-core` | 3 | Shared domain types (`Release`, `TrackerSource`, language enums) |
| `brarr-tracker-unit3d` | 4 | UNIT3D API client (HTTP + JSON deserialization) |
| `brarr-cli` | 5 | Command-line search tool |
| `brarr-orchestrator` | deferred | gRPC service + Axum/Askama/HTMX web UI (CSS artesanal) |
| `brarr-decision-service` | deferred | Rules engine for release selection |
| `brarr-plugin-host` | deferred | WASM sandbox for custom scraper plugins |
| `brarr-download-client` | post-spec | qBittorrent / SABnzbd clients (brarr replaces the \*arr core) |

Boundary rules:
- Parser ≠ HTTP client ≠ Rules engine ≠ Tracker impls. Never collapse layers.
- Traits (e.g., `TrackerProvider`) only when ≥2 implementations exist. No single-impl traits.
- Web UI is server-side rendered (Askama templates + HTMX). No SPA framework.

## Engineering Rules (non-negotiable, from spec)

- **TDD**: failing test first, using real fixtures in `tests/fixtures/`. Sample UNIT3D JSON responses (Matrix 1999 from two trackers) and MediaInfo dumps are drafted in `INITIAL_PROMPT.md` — use them, do not synthesize fake data.
- **No `unwrap()` / `expect()`** outside `#[cfg(test)]`. Propagate `Result`.
- **Errors**: `thiserror` in library crates, `anyhow` in binaries. No `Box<dyn Error>`.
- **Logging**: `tracing` only. No `println!` / `eprintln!` except CLI user output.
- **Types as documentation**: newtypes for IDs, enums for closed sets, `Option<T>` for optional. Avoid stringly-typed APIs.
- **No defensive `.clone()`** — prefer borrows; clone only when ownership genuinely required.
- **Language**: English identifiers and `///` docs. Portuguese only for user-facing strings.
- **Clippy**: `pedantic` lints enabled via `clippy.toml`.
- **Commits**: Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`).

## Workflow per task

1. Read the relevant section of `INITIAL_PROMPT.md`.
2. Confirm understanding before writing code.
3. Write a failing test with a real fixture.
4. Implement the minimum to pass.
5. Run `cargo test`, `cargo clippy`, `cargo fmt`.
6. Commit with a conventional message.

## Out of scope (per spec)

- Premature abstractions, single-implementation traits
- `Box<dyn Error>` in any production code
- Trading correctness for speed
- SPA / client-side framework for the admin UI
